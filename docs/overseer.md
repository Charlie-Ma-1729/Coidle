# Overseer（世界管理者）

Overseer 是一個特殊帳號，用**金鑰**登入（沒有密碼），登入後進的是「管理室」而不是商場。她能旁觀所有商場、管帳號與商場、寫隨機事件、調天氣、操控 NPC 商場，並留下完整的稽核紀錄與營運數據。

## 建立與登入（在伺服器上）
```bash
cd ~/文件/github/Coidle
npm run admin -- create-overseer          # 建立帳號「overseer」並印出金鑰（只顯示這一次，請存到密碼管理器）
npm run admin -- rotate-overseer-key      # 換一把新金鑰：舊金鑰與所有舊的登入立刻失效
```
網站登入頁底下的「管理者金鑰登入」貼上金鑰。金鑰以 scrypt 雜湊存在資料庫；一般的帳號密碼登入對 Overseer 一律拒絕（金鑰不能當密碼用）。同一個位址連續輸錯 5 次會鎖 15 分鐘；成功與失敗都寫稽核。Overseer 不能改密碼、不能自刪、不能被管理後台刪除；「overseer」「admin」「root」「system」「npc」「gm」不能被一般註冊。

`.env` 的 `ADMIN_TOKEN` 已經停用：所有 `/api/admin/*` 只認 Overseer 登入。伺服器上的 `npm run admin -- …` 指令列仍可用，並同樣寫入稽核紀錄。

## 管理室的分頁
| 分頁 | 內容 |
|---|---|
| 📊 即時數據 | 現在線上玩家、24 小時／7 天活躍、玩家與商場總數、伺服器運行時間與記憶體；折線圖（玩家、每分鐘請求／指令／錯誤、tick 耗時與事件迴圈延遲、記憶體），可選 3 小時～30 天；每日統計表；匯出樣本 CSV／JSON 與每日 CSV |
| 🏬 商場 | 每座商場：成員、等級、資金、線上人數；**旁觀**（唯讀）、改名、暫停／繼續／調流速、等級、資金、通知、成員（加入、移出、轉讓創辦人）、功能與區域旗標、解散。測試商場有標記 |
| 👤 使用者 | 搜尋、改暱稱、登出所有裝置、重設密碼（臨時密碼只顯示一次）、刪除 |
| 🏢 NPC 商場 | 全域自動出手開關與頻率；每座 NPC 的調整（改名、等級加減、分數／營收倍率、口碑與熱度加減、暫時隱藏、出手頻率、到期時間）；手動出手（搶客、邀請聯名、送貨救援）與代為回覆邀請、辦聯名活動、結束協議；NPC 動態紀錄 |
| 🎲 事件與天氣 | 寫隨機事件（有選項或公告型，每個選項 1–2 個白名單效果）、上下架、對指定或全部商場立刻觸發任何事件；調整天氣（晴／陰／雨／暴風雨、氣溫、持續遊戲小時）套用到全部或指定商場 |
| 🤖 AI 內容 | 預算與內容池、立即生成、待審事件與新常客的核准或拒絕、已上線內容的移除（沿用原本的功能） |
| 📜 稽核 | 誰、何時、做了什麼；依動作開頭與操作者篩選、往更早翻、匯出 CSV |

管理室是左側選單＋右側內容的版面（手機上選單變成頂部橫列）。商場與 NPC 的細項調整在右側滑出的面板裡做；刪除、重設密碼等危險操作會先跳出確認視窗；臨時密碼只在視窗裡顯示一次，有複製鈕。離開管理室去商場再回來，會停在原本那一頁。

## 返回管理室
Overseer 在任何商場畫面（旁觀、自己的測試商場、打開「世界」看名錄與 NPC）左上角都有「← 管理室」按鈕，任何面板開著都看得到；☰ 選單裡也有「返回管理室」。

## 旁觀
從「商場」分頁按「旁觀」，會用一般的遊戲畫面看那座商場，上方有「旁觀中・唯讀」提示：
- 所有會改動商場的請求在瀏覽器就被擋下，伺服器也只認成員（旁觀者打指令、時鐘、聯名都是 403）。
- 旁觀的 WebSocket 不算「在場」：不會讓商場被當成有人在（自動暫停照常），不計入線上玩家，也不更新「最近造訪」。
- 每位 Overseer 每座商場每 10 分鐘最多記一筆 `spectate.open` 稽核。

## 測試商場（獨立於世界）
```bash
npm run admin -- sandbox-mall overseer 12      # 把現有的 12 號商場轉成測試商場、轉給 Overseer、移除其他成員
npm run admin -- sandbox-mall overseer         # 沒給編號：新開一座全開的（最高等級、全區域、全科技、新手任務完成、資金 1 億）
```
測試商場：
- 不進名錄、排行與賽季，賽季也不發獎；
- 不能聯名、貿易、搶客，別人也找不到它、不能用邀請碼加入；
- NPC 不會對它出手、也不會邀請它；
- 「全部商場」的天氣與事件預設不含它（點名才會送去）；
- 營運數據的玩家與商場數不計它；
- 商場內部的模擬（天氣、稅務、AI 事件、遊戲內商戰對手）照常，才能測功能。

## 稽核與伺服器 terminal
每個管理操作（含失敗與被拒絕的）寫進 `audit_log`，同時印一行到伺服器 console：
```
[audit] 2026-11-25T08:30:11.000Z overseer(#2) mall.flag mall#3(測試商場) {"flag":"zone:f1","value":true,"status":200} ip=1.2.3.4
```
在伺服器上用 `journalctl -u coidle -f` 就是後台 terminal。紀錄裡密碼、金鑰、token 一律以 `***` 遮蔽，不會出現臨時密碼。事件類型：`overseer.login`／`.login.fail`／`.login.blocked`、`admin.denied`（非 Overseer 打管理 API）、`mall.*`、`user.*`、`npc.*`、`event.*`、`weather.set`、`ai.*`、`metrics.export`、`spectate.open`，以及指令列的 `overseer.create`、`mall.sandbox` 等（操作者是 `cli`）。

## 營運數據
每分鐘一筆樣本（保留 30 天）：線上玩家／有人在場的商場／WebSocket 連線數、24 小時與 7 天活躍玩家、玩家與商場總數、每分鐘請求／錯誤／指令／NPC 出手、tick 最長耗時、事件迴圈延遲、記憶體、運行時間。每日統計永久保存（日界線是台灣時間 00:00，`METRICS_TZ_OFFSET_HOURS` 可改）：活躍玩家、新註冊、尖峰線上、請求、指令、錯誤、NPC 出手、最慢 tick。「線上」只算有開著商場連線的玩家（旁觀與 Overseer 不算）；「活躍」是該時間之後有任何已登入請求。匯出：`GET /api/admin/metrics/export?kind=samples|daily&format=csv|json&from=&to=`。

## 一個玩家管多座商場
一位玩家可以同時是任意多座商場的成員（`memberships` 的主鍵是商場＋使用者）。大廳列出全部；進了遊戲後 ☰ 選單有「切換商場」，設定 → 商場與帳號也有。每座商場的指令、時鐘與 WebSocket 互不影響（有測試）。
