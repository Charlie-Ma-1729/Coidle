# 日本日曆（連假、盂蘭盆節、黃金週…）

遊戲日期本來就是真實的日本日曆（JST，從 2027-04-01 開始，星期幾與月份都是真的）。日曆功能讓「今天是不是國定假日、連休、盂蘭盆節…」影響**客流**與**業態需求**。程式在 `shared/src/game/calendar.ts`，測試在 `calendar.test.ts`（對照 2026–2031 的官方假日）與 `server/src/sim/sim.test.ts`。

- **純函式、只看遊戲日序**（和 `dayWeather` 同型）：不存檔、不需要 state migration。同一個日期永遠得到同一組結果，所以追趕、補算、分段推進都和即時推進完全一致。
- **全服同一個日曆**：伺服器基準時間讓所有商場同一天過同一個連假（見 `docs/cross-mall.md`）。真實 4 小時＝1 遊戲日，所以一個遊戲年約 61 個真實日；黃金週（4/29–5/6，8 天）約 32 個真實小時、盂蘭盆（8/13–16）約 16 小時、年末年始（12/29–1/3）約 24 小時。
- 「對上日本的現實日曆」指**遊戲日期對應真實日本日曆的規則**（2027 年起每年的假日都依真實規則推算），不是讓遊戲日期等於今天的真實日期。

## 國定假日（法定）
元日 1/1、成人之日（1 月第 2 個週一）、建國紀念日 2/11、天皇誕生日 2/23、春分之日（公式）、昭和之日 4/29、憲法紀念日 5/3、綠之日 5/4、兒童節 5/5、海之日（7 月第 3 個週一）、山之日 8/11、敬老之日（9 月第 3 個週一）、秋分之日（公式）、體育之日（10 月第 2 個週一）、文化之日 11/3、勤勞感謝日 11/23。

另外：
- **補假**：假日撞週日，順延到「之後第一個不是假日的日子」（2027 的 3/22、2029 的 2/12、4/30、9/24 都對得上官方）。
- **國民之休日**：前一天與後一天都是法定假日、本身不是假日也不是週日的日子（2026 的 9/22，銀色週）。
- 春分／秋分用 1980–2099 的標準近似公式。

## 休息日與連休
- `TimeInfo.offDay`＝週末、國定假日、或公司放假的長假（年末年始 12/29–1/3、黃金週 4/29–5/6、盂蘭盆 8/13–16）。**休息日用週末的客流曲線與倍率**（`weekendHourShare`／`weekendMult`），`TimeInfo.weekend` 仍然只代表週六日。
- **連休**：連續 3 天以上的休息日。不是長假季的連休（銀色週、三連休…）會有通用加成：家庭 ×1.15、觀光客 ×1.12、情侶 ×1.08、通勤族 ×0.85，停車場、旅館、旅行社、行李寄放需求小幅上升。長假季（黃金週、盂蘭盆、年末年始）已經有自己的數字，不重複疊加。

## 節日與習俗（`OBSERVANCES`，資料驅動）
每一項有「客群倍率」與「業態需求倍率」；全部相乘後夾在客流 ×0.3–2.2、需求 ×0.5–2.5 以內。主要的：

| 日子 | 效果 |
|---|---|
| 年末（12/29–31） | 上班族 ×0.4；在地客 ×1.3、家庭 ×1.25；超市、壽司、花店、居酒屋需求上升 |
| 新年（1/1–3） | 上班族 ×0.3；家庭 ×1.45、在地客 ×1.35、情侶／觀光客 ×1.25；懷石、服飾（福袋）、玩具、美妝需求上升 |
| 黃金週（4/29–5/6） | 家庭 ×1.45、觀光客 ×1.3、情侶 ×1.2、上班族 ×0.6；親子遊樂場、電影院、展望台、旅館、停車場需求上升 |
| 盂蘭盆節（8/13–16） | 上班族 ×0.45、在地客 ×0.85（返鄉）；家庭 ×1.35、觀光客 ×1.2；花店 ×1.5、行李寄放、旅館、旅行社需求上升 |
| 暑假／春假／寒假 | 學生與家庭小幅上升；親子遊樂場、電玩、補習班（夏期講習）等 |
| 賞花季（3/25–4/10）、紅葉季（11/10–30） | 觀光客、情侶、在地客上升；餐車廣場、啤酒花園、懷石、喫茶等 |
| 新生活旺季（3/20–4/10） | 文具、家電、洗衣、補習班、影印需求上升 |
| 情人節 2/14、白色情人節 3/14、聖誕 12/24–25 | 情侶客流 ×1.3–1.6；甜點、花店、飾品、Fine dining、蛋糕、玩具等 |
| 母親節、父親節、七夕、萬聖節、七五三、除夕、忘年會／新年會季 | 各自的小幅加成（母親節花店 ×1.9、七五三寫真館 ×1.7、除夕蕎麥麵 ×1.7、忘年會居酒屋 ×1.3…） |
| 發薪日（25 日，遇週末提前到週五） | 上班族 ×1.08、在地客 ×1.06；居酒屋、燒肉小幅上升 |
| 特定國定假日 | 成人之日（美容美髮、寫真館 ×1.9）、兒童節（玩具、親子遊樂場）、海之日、敬老之日、彼岸（花）、體育之日、文化之日（藝廊、書店）、勤勞感謝日 |

原本的隨機事件「連假人潮」（`holiday_rush`，只看月份擲骰）已退役，由日曆取代；夏日祭典等節慶事件仍是隨機事件。

## 平衡
- 全年平均客流（各客群 × 到訪量 × 休息日倍率 × 日曆倍率）比「只有週末、沒有日曆」多約 **+4%**（測試守在 0%–8%）。假日當天的差距很明顯，但全年不會膨脹；`docs/balance-report.md` 的營收數字因此會略高。
- 店面容量有限：假日人潮多了，滿座離開與缺貨也會變多，所以日曆是備貨與排班的策略點，不是單純的加成。畫面上的「📅 日本日曆」卡（營運頁、HUD 資金面板）提前顯示接下來 30 個遊戲日的假日與節日；HUD 的日期旁會標出今天的節日。客流預測圖（大數據分析科技）已含日曆。

## 給之後的功能用
`calendarDay(day)` 會回傳 `tags`（`holiday`、`long_weekend`、`golden_week`、`obon`、`new_year`、`year_end`、`school_break`、`payday`、`season_event`、`moving_season`…）。私鐵載客量、不動產的搬家旺季、自有品牌的檔期都可以直接重用（見 `docs/roadmap-extensions.md`）。
