# 股票市場 v1 與個人財務

玩家可以用**個人錢包**買賣 16 家虛構「集團」的股票。這些集團和商場無關——就像阪神電鉄之於阪神百貨：玩家現在經營的是「百貨」，將來才會長成「集團」；現在的股市只是讓玩家用閒錢投資、試著賺一點。**玩家商場的上市（IPO）還沒做。**

## 它是什麼、不是什麼
- 是給個人錢包的出口，也是日後「集團／IPO」的基礎（標的清單、價格序列、持倉、買賣、走勢圖、個人財務頁）。
- 不是很深的玩法：標的是虛構的，扣掉手續費與稅，期望報酬略為負，更像有風險的存錢罐。
- **不會吸走商場後期堆積的資金**：市場只動個人錢包，錢包的錢只來自股利、撤資、賣股份。要吸商場資金得等集團／IPO／商場投資其他公司。

## 價格（`shared/src/game/market.ts`）
- 價格是「**伺服器私有種子 ＋ 時間**」的純函式，**不存歷史**：每真實 **1 小時**一個價格點，從世界起點（`WORLD_EPOCH_MS`）逐點累加，重啟後重算結果一樣（~1 萬步 × 16 家，可忽略）。種子存在 `meta.stock_seed`（第一次用到時產生），客戶端只拿得到「現在以前」的價格。
- `price = 基準價 × exp(x + 世界訊號)`，其中隨機遊走 `x[t+1] = x[t]·(1−κ) + beta·大盤 + 個股 + 消息`：
  - 16 家共用同一個**大盤成分**（彼此有相關性）；`beta` 與個股波動依性格（防禦型低、一般、成長型高）；
  - **消息**：每家平均約 12 真實天一次、±6–12% 的一次性跳動，附一句新聞標題（`eventAtHour`，純函式）；
  - **弱回歸**：半衰期約 30 真實天，只防止價格漂到離譜，不是穩賺的套利依據；
  - `x` 夾在 ±0.8（對數）以內。
- **世界訊號**（`SIGNALS`）：已發生的日曆與天氣——長假連休、假日、發薪日、雨天、酷暑與嚴寒、氣溫、搬家旺季、年度末、換季寒暖差、年末年始——取近 3 個遊戲日（今天、昨天、前天）加權平均，幅度最多 ±3%（`SIGNAL_AMPLITUDE`），所以價格有故事可讀，但仍以隨機為主。只用「已發生」的值，不偷看未來（避免「天氣預報→提前買進」的保證獲利）；日曆是公開可預測的，所以幅度刻意小，遠低於波動與摩擦。
- 遊戲日來自伺服器時鐘（`serverTickAt` → `dayOfTick`）。**伺服器時鐘的錨點若被改，世界訊號的歷史會跟著變**（錨點正常情況下只在第一次啟動時決定一次）。

## 買賣規則（`server/src/world/market.ts`）
| 項目 | 規則 |
| --- | --- |
| 手續費 | 買、賣各收 0.5%（無條件進位） |
| 稅 | 賣出的已實現獲利課 20.315%（日本證券所得稅）；平均成本法，成本含買進手續費；虧損不退稅、不和其他持股相抵 |
| 每日買進上限 | 每個遊戲日（4 真實小時）最多買 ¥1,000,000（股款，不含手續費） |
| 持股上限 | 單一集團持股市值最多 ¥3,000,000（買進後） |
| 不能做的事 | 放空、配股利、Overseer 帳號交易 |
| 價格 | 買賣都用「當下這一小時」的價格，沒有滑價或價格衝擊 |

錢包與持倉、成交紀錄、錢包流水包在同一個資料庫交易裡（`repo.tx`）。成交寫稽核紀錄（`stock.buy`／`stock.sell`），讓 Overseer 查串通。

**資金的流向**：買賣只在「錢包 ↔ 持倉」之間；手續費與稅離開遊戲。對手是系統流動性，所以**獲利是系統發放的**——每日上限、持股上限、稅與手續費就是控制閥，列為觀察項目（`docs/balance-report.md` 的後續調整）。沒有玩家間轉錢。

## API
`GET /api/market`（現價、24 小時漲跌、迷你走勢、持有、最近消息、今日已買額）、`GET /api/market/:key/history?hours=`（最多 30 天）、`GET /api/me/portfolio`、`POST /api/market/:key/buy|sell`（`{shares}`；402 錢包不足、409 超過上限或持股不足、404 無此標的、403 Overseer）。

## 個人財務頁（`client/src/screens/Personal.tsx`）
目前沒有也不需要「個人頁」以外的地方看錢：個人財務集中成一個視窗，Lobby（沒有商場也看得到）與遊戲內 ☰ 選單共用（`store.personalPage`／`openPersonal`），四個分頁：
1. **總覽**：總資產、資產組成（錢包、商場持股、股票）、待處理的出價與注資申請、開新商場成本。
2. **商場股權**：各商場持股（可展開處理：撤資、出價賣給其他股東、無償轉讓）、跨商場的出價與注資申請（`GET /api/me/equity`）。
3. **股市**：16 檔股價表 → 走勢圖（1／7／30 天）＋買賣面板（含手續費、稅試算）→ 我的持倉。
4. **明細**：錢包流水（`GET /api/me/ledger`，最近 100 筆，可篩選）。

商場團隊頁的 `EquityCard` 只剩**這座商場**的股權表、注資換股、股利；自己的錢與股份都在個人財務。

### 錢包流水（DB v13 `wallet_ledger`）
`repo.addCash(userId, delta, { kind, note, at })` 在同一個地方寫入流水，所以所有動錢包的地方都要帶上它（`dividend`、`buyback`、`share_sale`／`share_buy`、`capital`、`founding`、`stock_buy`／`stock_sell`）。不回填舊資料。測試保證流水加總與錢包對得上。

## 資料（DB v13）
`stock_positions(user_id, company, shares, cost_total)`、`stock_trades(…day…)`、`wallet_ledger`；都隨使用者刪除而一併刪除（`ON DELETE CASCADE`）。

## 未來怎麼延伸
1. **集團／IPO**：玩家商場長成集團並上市，沿用 `g:<id>` 鍵與持倉、價格序列；玩家集團的價格由基本面（營收、口碑）取代隨機種子，關係人不能互相買賣、內線禁止交易期、金融操作用更嚴的落後門檻（見 `docs/roadmap-extensions.md`）。
2. **價格衝擊**：用全服的淨買賣量推價，讓大戶有代價、也讓玩家之間的行為互相影響。
3. **股利**：集團配息（扣 20% 所得稅，沿用 `splitDividend` 的概念），需要新的資金來源控管。
4. **Overseer 工具**：市場消息覆寫（像 NPC 的 override）、暫停交易、調整上限。
5. **更多玩法**：放空、損益相抵、融資、指數基金、持股排行（要小心：這些都會放大「系統發放獲利」）。
6. **更真實的估值**：商場持股改用「現金＋店面與設備折舊＋營收倍數」，見 `docs/equity.md`。

## 已知限制
- 市場對手是系統流動性，獲利是系統發放的；目前靠上限與稅控制，上線後要看實際的錢包成長。
- 同一個玩家多開帳號、帳號串通無法由規則分辨；靠稽核紀錄查。
- 價格每小時才更新一次，沒有盤中。
- 世界訊號依賴伺服器時鐘錨點；改錨點會讓歷史價格改變。
