# 股票市場 v2 與個人財務

玩家可以用**個人錢包**買賣 40 家虛構「集團」的股票，**商場也能用公司資金入股**（法人投資，見下）。這些集團和商場無關——就像阪神電鉄之於阪神百貨：玩家現在經營的是「百貨」，將來才會長成「集團」。**玩家商場的上市（IPO）、公開收購（TOB）還沒做**（設計在 `docs/group-ma.md`）。

> **內容規則**：股市的內容（新聞、標的介紹）**可以出現真實地名**（東京、橫濱…），**不可以出現真實品牌／企業／商品名**；公司、指數名全是虛構。商場內容（日報、評價、品牌名…）維持「不點名真實地點」。

## 它是什麼、不是什麼
- 是個人錢包的出口、商場資金的第一個出口（法人入股，有嚴格上限），也是日後「集團／IPO／併購」的基礎（標的清單、股數與市值、價格序列、持倉、指數、消息庫、配息）。
- 不是很深的玩法：標的是虛構的，扣掉手續費與稅，期望報酬略為負（機器人驗證見 `docs/balance-report.md`「股市 v2」），更像有風險的存錢罐。

## 開市時間（`shared/src/game/market/exchange.ts`）
仿東京證券交易所，**用遊戲內時間（JST）**：
- 交易日＝平日、非國定假日（用 `holidayOf`，不是 `offDay`：黃金週、盂蘭盆是公司放假，東證照開）、非 12/31–1/3。
- **前場 9:00–11:30、午休、後場 12:30–15:30**。1 真實分鐘＝6 遊戲分鐘，所以一個價格步＝6 遊戲分鐘＝1 真實分鐘；一天 240 步，開市 **55 步**（前場 25、後場 30）。四個邊界都剛好是 6 分鐘的倍數。
- 換成真實時間：遊戲日 4 真實小時，一個遊戲日裡開市約 25＋30 真實分鐘、午休 10 分，一個遊戲週（28 真實小時）開 5 天。**休市占真實時間的大半**，所以休市時有預約單。
- 休市時價格不動；消息照常發生，累積到下次開盤用**跳空**反映（收盤後的公告、假日的消息）。
- `marketStatus(realMs, clock)` 回傳 `{session, open, day, clock, nextOpenAt, nextCloseAt, reason}`，前後端共用。

## 價格引擎（`shared/src/game/market/engine.ts`，`PriceEngineV2`）
價格是「**伺服器私有種子 ＋ 時間**」的純函式，只在開市步計算，不存歷史：
- 一個交易日＝開盤跳空（大盤＋個股＋休市期間累積的消息＋除權息）→ 55 個價格步 → 收盤。`price = 基準價 × exp(x + 世界訊號)`，`x[t+1] = x[t]·(1−κ) + beta·大盤 + 個股 + 消息`。
- 每遊戲日總變異與 v1 相當（σ_d＝2·σ_h）：盤中 80%、開盤跳空 20%（休市越久跳空越大）；弱回歸（半衰期約 30 真實天）；`x` 夾在 ±0.8。
- **制限值幅**：相對前日收盤 ±15%（`PRICE_LIMIT`）。價格整數、最低 ¥10。
- **世界訊號**（`signals.ts`）：日曆與天氣（長假連休、假日、發薪日、雨天、酷暑與嚴寒、搬家旺季、年度末、換季寒暖差、年末年始），近 3 個遊戲日加權，幅度 ±3%。只用「已發生」的值。伺服器時鐘錨點若被改，歷史會變。
- **優化**：不存每個點。每個交易日只存 OHLC 與收盤的隨機遊走偏離；盤中價格用小型 LRU 快取（`INTRADAY_CACHE_MAX`），被擠出後從前一日收盤決定性重算；每個交易日只算一次。冷啟動實測：**250 個交易日 × 40 檔約 125 ms，750 個約 290 ms**，所以不需要把檢查點寫進資料庫（`market2.test.ts` 有 <4 秒的基準）。
- **v1 → v2 的接續**：舊引擎（每真實小時一點）凍結成 `shared/src/game/market.ts` 的 `PriceEngine`（只算既有 16 檔）。第一次啟動 v2 時伺服器把當下時間記進 `meta.market_v2_start`，**v2 從下一個交易日開盤開始**（開盤前、休市或開市中都一樣；開市中啟動就順延到隔天）；既有 16 檔從 v1 在切換點的狀態接續（持倉與成本不受影響），新增 24 檔從基準價「新上市」。切換到 v2 起點之前，列表用 v1 價格（標示未上市、不能交易），走勢圖用 v1 的歷史。

## 消息面
- **內容庫**：AI 預先生成並由 Claude 逐則審核過、存進 repo 的 `shared/src/game/market/news.data.json`（格式、覆蓋矩陣、審核紀錄見 `docs/market-news.md`）。執行期不呼叫模型。
- **取用**（`news.ts`，`NewsEngine`）：純函式（種子＋遊戲日＋標的），**隨機或依條件**：文案可限定板塊、月份／季節、日曆（連休、黃金週、盂蘭盆、年末年始、發薪日…）、天氣、決算期；符合當天條件的文案權重 ×3，當天有明顯日曆／天氣條件時板塊與全市場消息機率略升。
- **來源**：公司自身（約每 60 遊戲日一則）、決算（每季一次，公開日曆，收盤後公告→隔日跳空）、分析師評等（小幅）、**傳聞→證實／否認**（先反映 q·R，證實機率 q 時補 (1−q)·R，否認時回吐 q·R，是 martingale）、板塊消息、全市場消息（各檔依 beta）。
- **零期望值守則**：所有跳動方向五五波、幅度對稱；`market2.test.ts` 檢查傳聞後的額外跳動平均接近 0，機器人策略驗證沒有「看標題買賣」的穩賺。
- 內容庫沒有符合條件的文案時退回內建短句，不會當機。`GET /api/market/news` 回傳「已經發生的」消息（含本文）；法人持股超過 5% 的「大量持有報告」也在這裡（無價格效果）。

## 買賣規則（`server/src/world/market.ts`）
| 項目 | 規則 |
| --- | --- |
| 開休市 | **休市不能直接買賣**（409，含下次開盤時間）；開市中用「當下這一步」的價格，沒有滑價或價格衝擊 |
| 預約單 | 休市時下「開盤市價單」：在**下單之後的第一次開盤**用開盤價成交；成交時才檢查錢包、每日額度、持股上限，失敗標記拒絕；每人最多同時 10 張；賣單不能超過持股（扣掉其他預約賣單） |
| 手續費 | 買、賣各收 0.5%（無條件進位） |
| 稅 | 賣出的已實現獲利課 20.315%；平均成本法，成本含買進手續費；虧損不退稅、不和其他持股相抵 |
| 每日買進上限 | 每個遊戲日（4 真實小時）最多買 ¥1,000,000（股款，不含手續費） |
| 持股上限 | 單一集團持股市值最多 ¥3,000,000（買進後） |
| 配息 | 有配息的標的在**除權息日**（配息月的下一個月第一個交易日，開盤時價格下跌相同金額）入帳給持有人，每股＝年配息率×基準價÷2，扣 20.315%；`stock_dividends` 冪等；買賣與列表前都會先結算，不依賴排程準時 |
| 不能做的事 | 放空、Overseer 帳號交易 |

錢包與持倉、成交紀錄、錢包流水包在同一個資料庫交易裡（`repo.tx`）。成交寫稽核（`stock.buy`／`stock.sell`／`stock.order`）。

**資金的流向**：買賣只在「錢包 ↔ 持倉」之間；手續費與稅離開遊戲。對手是系統流動性，**獲利與配息是系統發放的**——每日上限、持股上限、稅與手續費是控制閥。配息（除權息日價格同額下跌）的淨效果略為負（稅），但價格有弱回歸，淨效果近似持平，列為觀察項目。沒有玩家間轉錢。

## 法人投資（商場用公司資金入股）
`equity.md` 原則 4 的第五條資金路徑，規格與不變量見 `docs/group-ma.md`，常數與函式在 `shared/src/game/ma.ts`、畫面型別在 `corporate.ts`：
- 只有**管事的人**（`authorityOf`）能下單，測試（sandbox）商場不能；落後伺服器超過 **1 遊戲日**（`financeBlocker`）不能下單；只能在開市中買賣、不能預約。
- 單一標的最多流通股的 **10%**、全部投資市值最多商場現金的 **40%**（`corporateCap`）；手續費與賣出獲利稅同個人；配息入公司資金（扣稅）。
- 持股變動跨過 **5%**（`disclosureCrossing`）→ 公開一則「大量持有報告」（`stock_disclosures`，無價格效果，避免炒作）。
- 狀態：`mall_positions(mall_id, company, shares, cost_total)`（DB 表，不放進商場存檔，所以配息與估值不必掃全部商場）。資金變動走 `MallService.mutate`，和 DB 持倉包在同一個 `repo.tx`。
- 估值：`WealthView.corporate` ＝ 我的持股比例 × 商場持有的股票市值；`stakes[].value`（帳面價值）仍只算帳上現金，撤資、出價與增資價格不變（保守）。
- API：`GET /api/me/corporate`、`POST /api/malls/:id/portfolio/:key/buy|sell`（稽核 `portfolio.buy|sell`）。畫面：股市詳情頁「交易帳戶」切換到「〈商場〉（公司資金）」。

## API
`GET /api/market`（市場狀態、指數、現價、較前日收盤漲跌、開高低、制限值幅、市值、迷你走勢、持有、預約單、今日已買額）、`GET /api/market/status`、`GET /api/market/news?limit=`、`GET /api/market/:key/history?range=1d|5d|1m|3m|all`（1d／5d 是盤中每步一點，1m／3m 是最近 30／90 個遊戲日的日 K，all 是全部；v2 起點之前的交易日不夠時，伺服器用同一個價格引擎往回推算 130 個交易日（約半年；從基準價開始走，再把每檔在對數上線性拉到真正的起點價格，所以圖接得起來；只用來畫圖，價格、買賣與持倉成本不受影響，同種子永遠同結果），所以每個區間、每一檔（含新上市的）一開始就有完整的盤中與日 K；含消息標記與前日收盤）、`GET /api/me/portfolio`、`POST /api/market/:key/buy|sell`（`{shares}`；402 錢包不足、409 休市／未上市／超過上限／持股不足、404 無此標的、403 Overseer）、`POST /api/market/:key/order`（`{side, shares}`）、`POST /api/market/orders/:id/cancel`、`GET /api/me/wealth/history`、`GET /api/me/stock-summary`。

## 個人財務頁（`client/src/screens/Personal.tsx`）
四個分頁，Lobby 與遊戲內 ☰ 選單共用：
1. **總覽**：總資產、資產組成（錢包、商場持股、股票、法人投資）、**資產走勢**（每遊戲日 16:00 JST 記一筆 `wealth_snapshots`，圖上至少兩筆才畫）、待處理的出價與注資申請、開新商場成本。
2. **商場股權**：各商場持股（撤資、出價賣給其他股東、無償轉讓）、跨商場的出價與注資申請。
3. **股市**：市場狀態列（開休市、遊戲時間、下次開盤倒數）、兩個指數、股價表（搜尋、板塊篩選、排序）、**消息**分頁（標題與本文）、走勢（今日／5 日／1 個月／3 個月／全部；日線可切 K 線並疊 5 日、20 日均線；手指或滑鼠移到圖上會顯示那一點的價格或開高低收與漲跌）、買賣面板（休市時改成預約買賣）、預約單、我的持倉、已實現損益／配息／手續費／稅的彙總、交易帳戶切換（個人錢包／公司資金）。
4. **明細**：錢包流水（可篩選；股票篩選含配息）。

## 未來怎麼延伸
1. **集團／IPO／併購**：玩家商場長成集團並上市，沿用 `g:<id>` 鍵與持倉；基本面取代隨機種子；關係人不能互相買賣、內線禁止交易期。見 `docs/group-ma.md`、`docs/roadmap-extensions.md`、`docs/future-industries.md`。
2. **價格衝擊**：用全服的淨買賣量推價。
3. **Overseer 工具**：市場消息覆寫、臨時休市／暫停交易、調整上限。
4. **更多玩法**：放空、損益相抵、融資、指數基金／ETF、持股排行（都會放大「系統發放獲利」，要小心）。
5. **更真實的估值**：商場持股改用「現金＋店面與設備折舊＋營收倍數」（`docs/equity.md`）。

## 已知限制
- 市場對手是系統流動性，獲利與配息是系統發放的；靠上限與稅控制，上線後要看實際的錢包成長。
- 同一個玩家多開帳號、帳號串通無法由規則分辨；靠稽核紀錄查。
- 世界訊號依賴伺服器時鐘錨點；改錨點會讓歷史價格改變。
- 世界訊號的水位在日界線跳動（天氣是否有預報會影響可預測性）；機器人驗證的訊號預測策略淨報酬仍為負（−0.69%，含手續費），幅度只有 ±3%。
- 價格單位是 1 日圓，沒有東證的呼値與 100 股單位（本版不做）。
