# 擴充空間：股票市場、IPO、事業擴張（只保留，尚未實作）

目標玩法：商場賺了錢之後有地方花——**投資其他公司（股票市場）→ 自己的公司 IPO → 擴張事業（私鐵、不動產、自有品牌…）**。這也是 `docs/balance-report.md` 記載的「後期資金堆積」問題的出口。

**這份文件只寫約定，不新增欄位、不加功能。** 目的是讓現在做的東西（伺服器基準時間、信件 `at_tick`、日曆）不會擋住未來的玩法，並且寫下新玩法必須遵守的不變量。

## 現有的接口（新玩法直接用）
| 接口 | 位置 | 用途 |
|---|---|---|
| **伺服器基準時間** `serverTickAt()`／`serverRealMsAt()` | `shared/src/game/time.ts`；錨點存在 `server_clock` | 全服共用的時間軸。股價、配息、IPO 結算都用它；**沒有商場能比它快** |
| **信箱 `at_tick`** | `mall_mailbox`、`sim/mail.ts` 的 `applyMail`（依 `kind` 分派） | 在伺服器 tick 生效的跨商場效果。新增 `dividend`、`ipo_proceeds`、`share_trade` 只要加一個 case；落後的商場模擬到那個 tick 才收到 |
| **互動門檻** `assertCanInteract()` | `MallService`、`INTERACT_MAX_LAG_TICKS` | 落後太多的商場不能發起跨商場互動。金融操作建議用更嚴的門檻（0–1 遊戲日），避免用舊資訊套利 |
| **日曆** `calendarDay(day).tags` | `shared/src/game/calendar.ts` | 私鐵載客量（連休、發薪日）、不動產搬家旺季（`moving_season`，3–4 月）、自有品牌的檔期（情人節、聖誕…）直接重用 |
| **決定性序列** | `(seed, tick)` 決定亂數；NPC 與天氣是時間的純函式 | 股價＝以伺服器 tick 為種子的決定性序列，全服同價，追趕與即時推進結果一致 |
| **貿易的資金守恆** | `world/trade.ts`（手續費消失、來回只會越轉越少） | 股票交易沿用：寄出方在自己狀態當下扣款、收款方用 `at_tick` 信件入帳，不會憑空複製資金 |
| **名錄的公開欄位** | `mall_directory`、`world.test.ts` 的欄位白名單 | IPO 要公開財務時，**新增一組明確選擇加入的欄位**，不要放寬現有欄位 |

## 一個玩家多座商場：經營權與股權要分開
現在 `memberships`（商場＋使用者，一位玩家可以有任意多座）只代表**經營權**：誰能對商場下指令。`is_owner` 是創辦人，不是持股；資金屬於商場，不屬於成員。未來做股市與 IPO 時：

- **股權已經做了**（`holdings`、`wallets` 等，DB v11–v12，詳見 `docs/equity.md`）：創辦人起始 100%、持股過半是實際控制人、退出要賣給其他股東或撤資（商場回購）、股利按比例扣稅、注資換股（先買庫藏股再發新股）、起始資金每位玩家一次、持股 ≥ 20% 視同經手。股市與 IPO 在它上面接：持有別人的股票不該讓你能操作別人的商場；IPO 就是釋出一批新股。**怎麼往下接，見 `docs/equity.md` 的「未來怎麼延伸」。**
- **股票市場 v1 已經做了**（DB v13，詳見 `docs/stock-market.md`）：玩家用個人錢包買賣 16 家**虛構集團**（和商場無關，如阪神電鉄之於阪神百貨）；價格是（種子, 時間）的純函式，標的鍵 `g:<id>`；手續費、證券所得稅與每日／持股上限是控制閥。**還沒做**：玩家商場長成集團並上市（IPO）、集團股利、價格衝擊、放空、Overseer 市場工具——下面的關係人與內線限制要等玩家集團上市時才用得上。
- **法人入股（股市 v2 一起做，商場資金第一次碰股市）**：商場用公司資金買賣虛構上市集團的股票，持股放在資料表 `mall_positions`（DB v16），由伺服器層同步下單（資金走 `MallService.mutate`、和持股更新包在同一個 `repo.tx`；**已做完**，見 `docs/stock-market.md`「法人投資」）；這是 `docs/equity.md` 原則 4 的**第五條**資金路徑，規格、上限與「不做什麼」見 `docs/group-ma.md`，純規則在 `shared/src/game/ma.ts`。商場互相入股、玩家商場 IPO、公開收購（TOB）仍然只有設計。
- **「關係人」的判斷重用現有的 `repo.areRelated`**（共同經營者，見 `docs/cross-mall.md` 的「關係企業」），再加上「持股達一定比例也算關係人」。同一個玩家的關係企業之間：
  - 不能互相買賣股票（防洗盤與自買自賣拉抬股價）；
  - 不能配息或增資給對方（防把錢從一座搬到另一座）；
  - 股票交易同樣走 `assertCanInteract`，並對金融操作用更嚴的落後門檻（0–1 遊戲日）。
- **內線限制**：經營者在財報、IPO、重大事件公告前後有一段「禁止交易期」（用 `at_tick` 與日曆決定），避免用經營資訊炒股。
- **配息與增資用信箱**（`dividend`、`ipo_proceeds`），沿用「寄出方當下扣款、收款方用 `at_tick` 信件入帳」，全服資金守恆（只因手續費與稅變少）。
- 賽季獎金已經是一位玩家只領一份（`SEASON_ONE_REWARD_PER_PLAYER`）；持股帶來的收益也要有同樣的上限思維，避免多開帳號堆股息。
- 兩個不同帳號串通無法由規則分辨，要靠 Overseer 看 `trades`、之後的 `share_trades` 與稽核紀錄；文件與介面都不假裝能完全擋住。

## 約定
1. **新事業線＝`MallState` 的新選填欄位**。保留名稱：`ventures`（私鐵、不動產、自有品牌各一個子項）、`portfolio`（持股）、`listing`（本公司的上市資料）。選填欄位不需要升狀態版本；真的需要改既有欄位時，沿用 `sim/migrate.ts` 的 migration 鏈。
2. **每條事業線在 `stepTick` 裡各自一個步驟函式**（`stepVenture(s, ctx)`），收支進同一套每日帳（`today`／`reports`／稅），這樣稅、報表、財務頁、資金出口都自動涵蓋。
3. **跨商場的部分（股市、IPO）放在伺服器層**（像 `world/` 底下的服務），用信箱把結果交給商場；模擬引擎仍然是純函式、不讀別的商場。新資料表走資料庫 migration（`db.ts` 的 `MIGRATIONS` 陣列加一項）。
4. **全服共用的價格不存進商場**：用伺服器 tick 當種子算出來，或存在伺服器層的表裡，由 Overseer 可調整（像 NPC 的覆寫）。
5. **UI 掛在既有的世界頁籤或事業頁**：避免新增一個新的頂層入口。

## 新玩法必須遵守的不變量
- **決定性**：同樣的 `(seed, tick)` 與同樣的輸入永遠得到同樣的狀態；追趕、補算、分段推進與一次補算等價。
- **資金守恆**：除了明確的手續費與稅，錢不會憑空出現；任何買賣、配息、IPO、併購都要有測試證明「全服總資金只會因手續費與稅變少」（個人錢包與商場現金分開算）。**錢進出商場的路徑是封閉清單**（`docs/equity.md` 原則 4，現在五條）：新玩法要碰商場資金，先改那一條，不要在別處偷開。
- **依伺服器時間**：跨商場的效果用伺服器 tick 起算；冷卻與每日上限用真實毫秒（兩者等價）。
- **公開資料界線**：資金、庫存、成員、種子不外流；新增的公開欄位要有白名單測試。
- **測試商場（sandbox）不參與世界**：不能買賣股票、不能被投資，也不進行情。
- **玩家看不出誰是 NPC**：NPC 公司可以上市、被投資，介面與規則一樣。

## 想像中的第一版（參考，不是承諾；股市 v1 已改成虛構集團，見 `docs/stock-market.md`）
- **股市**：NPC 公司（現有 8 座 NPC 商場）與已 IPO 的玩家商場都有股價；股價＝基本面（營收、口碑、日曆季節）× 決定性波動。玩家用閒錢買賣，有手續費與每日上限，用 `share_trade` 信件在伺服器 tick 結算；配息用 `dividend` 信件。
- **IPO**：商場等級／營收達標、合規沒有紅字、開張滿一定時間才能申請；募資進 `ipo_proceeds`，同時選擇公開財務欄位；之後有股東壓力（配息、成長目標）當作取捨。
- **事業擴張**：私鐵（沿線客流＝日曆的連休與發薪日，反過來為商場導客）、不動產（租金收入與搬家旺季）、自有品牌（和既有的研發工坊、品牌名組合接起來，檔期跟著日曆）。
